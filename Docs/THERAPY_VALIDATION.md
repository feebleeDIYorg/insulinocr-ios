# Therapy model validation

The current portable suite contains 57 tests. `TherapyReferenceMatrixTests`
adds an independent insulin oracle and broadens the numerical parameter matrix.
This is numerical model evidence, not clinical validation or OCR acceptance.

| Check | Matrix | Absolute tolerance |
|---|---|---|
| Insulin IOB against original OpenAPS helper | DIA 180–600 minutes in 30-minute steps × peaks 75/55/45 minutes × 4 amounts × 9 ages; 1,620 vectors | 1e-9 IE |
| Minute basal fold against ten-second fold | All 45 DIA/type combinations; irregular boundaries, several rates, gaps and clipping at capture | 0.005 IE |
| COB rational boundary values | All 13 durations from 120–480 minutes × 4 amounts × 6 ages | 1e-9 g |
| Insulin curve bounds and monotonicity | Every minute of all 45 DIA/type combinations | Monotonicity slack 1e-12 IE |

## Observed basal completeness

Computation model version `openaps-exponential+loopkit-cob/1.2.0` adds a source
completeness policy without changing either numerical kernel. Screenshot-sourced
data must contain continuous, non-overlapping basal intervals across the DIA
ending at capture. Missing intervals are not zero delivery; zero delivery needs
an explicit observed zero-rate interval. Gaps and overlaps withhold basal and
total IOB. Public incomplete-case presentations withhold all four activity cards.
Only floating-point boundary noise up to one microsecond is tolerated.

Forecasts validate that same frozen observation window, then decay the observed
past doses. They do not require or assume future basal delivery. Tests cover
an empty source, a trailing gap, an interior gap, overlap, explicit zero-rate
coverage and complete forecast decay. Numerical oracle/integration tests use
explicit synthetic dose lists without claiming complete screenshot history.
Existing saved computation versions remain unchanged.

## Insulin oracle provenance

`Fixtures/OpenAPSInsulinGoldens.json` is synthetic numerical data generated by
executing the original MIT-licensed OpenAPS implementation at commit
`88cf032aa74ff25f69464a7d9cd601ee3940c0b3`:
[lib/iob/calculate.js](https://github.com/openaps/oref0/blob/88cf032aa74ff25f69464a7d9cd601ee3940c0b3/lib/iob/calculate.js).
The input source SHA-256 is
`ca8b738cd5c4db037760949c09028448e01b155680f0bac6c3c081e24300d348`.
The generator refuses another source hash. It evaluates upstream code rather
than reimplementing the Swift formula. No GPL source is used.

The oracle calls `iobCalcExponential` with custom peaks and continuous ages.
The outer OpenAPS entry point rounds ages to whole minutes; that wrapper is
deliberately bypassed because InsulinOCR evaluates partial-minute basal doses.
Each vector records DIA, peak, age, dose and expected remaining insulin.
Ages include the start, either side of the peak, half the DIA, and either side
of the end. This does not compare the upstream activity-rate output.

To regenerate after downloading the pinned source into ignored build storage:

```sh
mkdir -p build/MathReference
curl --fail --location 'https://raw.githubusercontent.com/openaps/oref0/88cf032aa74ff25f69464a7d9cd601ee3940c0b3/lib/iob/calculate.js' --output build/MathReference/openaps-calculate.js
node Scripts/generate_insulin_goldens.cjs build/MathReference/openaps-calculate.js Packages/InsulinOCRCore/Tests/InsulinOCRCoreTests/Fixtures/OpenAPSInsulinGoldens.json
swift test --package-path Packages/InsulinOCRCore
```

## COB and integration scope

COB expected fractions are independent rational values for the documented
piecewise-linear absorption curve: 1 before/at the ten-minute delay, 8/9 at
15% of absorption, 10/27 at 50%, and 0 at/after completion. Existing tests also
exercise values around transitions. The basal resolution comparison uses the
same integrator with different step sizes; its purpose is to bound minute
discretization error, while the separate insulin oracle validates the kernel.

Local passing evidence is `build/core-therapy-matrix-tests.log` (ignored).
CI uses only the committed synthetic vectors. Real-image QA, complete-case
history checks, target-device performance and TestFlight remain separate gates
in `ACCEPTANCE_STATUS.md`.
